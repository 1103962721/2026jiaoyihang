服务端 Qt
1. 打开服务端显示主界面；端口默认来自协议默认端口；客户端列表为空。
2. 点击“开始监听”创建监听 socket；进入“监听中”；等待客户端连接。
3. 收到客户端 HELLO列表新增客户端：IP、状态、备注、队伍准备状态、组队码、操作列。
4. 按 READY 显示状态READY 0 = 未准备；READY 1 = 已准备。只有已准备客户端会进入全局出发/自动开始目标集合。

客户端 Qt
1. 打开客户端自动加载配置；刷新窗口列表；尝试自动绑定“三角洲行动”游戏本体窗口。
2. 连接服务端输入/读取服务端 IP，连接 TCP；连接成功后发送 HELLO；开始心跳。
3. 添加/绑定点击任务选择游戏窗口；设置客户区点击坐标；任务启用后可被 TRIGGER 触发。
4. 用户切换准备点击准备按钮：发送 READY 1；取消准备：发送 READY 0。断线时本地清回未准备。
准备 / 未准备分支

未准备路线（READY 0）

  • 服务端列表显示“未准备”。
  • 全局出发不会触发该客户端。
  • 自动开始不会把它加入 targets。
  • 仍然可以右键/行内执行部分单客户端操作：获取组队码、识别队伍状态、自雷、备注、踢出等。
  • 如果客户端断线或任务窗口失效，客户端本地会清回未准备。

已准备路线（READY 1）

  • 服务端列表显示“已准备”。
  • 手动“全局出发”会发送 TRIGGER 到所有已准备客户端。
  • 自动开始开启后，服务端会周期性识别队伍状态。
  • 识别到队伍满员（例如 2/2）后，服务端触发全局出发。
  • 出发后进入匹配/加载/进对局 OCR 阶段，最后发自雷请求。

自动开始路线（当前最新：100ms tick，单请求不堆积）
服务端 Qt
1. 勾选“自动开始”启动 autoStartTimer；当前最新 tick = 100ms。
2. 仅扫描已准备客户端connected && ready 才进入 targets；未准备客户端跳过。
3. 请求队伍状态客户端空闲时发 TEAM_READY_REQUEST；忙碌/actionRunning 时等待下一轮。
4. 判断满员所有等待目标 teamReadyState == 1 → 全局出发；否则继续识别。
5. 满员后全局出发发送 TRIGGER；每个已准备客户端进入 AfterTriggerDelay，等待 1 秒。
6. 匹配阶段 OCR识别右下角 (1945,1261,500×60)：看到“取消行动” → 显示“匹配中”。
7. 加载阶段 OCR右下角不再有“配装/出发/取消行动”，或已见取消行动后 No text found → 显示“正在加载”。
8. 对局阶段 OCR识别左上角 (0,0,300×60)：看到“机密/普通/绝密” → 显示“进入对局”。
9. 发送自雷请求显示“自雷中”；等待 SELF_THUNDER_RESPONSE。

客户端 Qt
1. 收到队伍状态请求执行一次队伍状态 OCR；解析 [x/n] 或失败。
2. 回传 TEAM_READY满员 state=1；未满 state=0；失败/无效 state=-1。
3. 收到 TRIGGER倒计时结束后点击启用任务窗口。
4. 收到通用 OCR 请求按服务端下发区域截图 → UmiOCR → 回传文本或错误。
5. 收到自雷请求绑定窗口有效时执行自雷流程：等 8s → 贝塞尔/相对下拉 → G/G → ESC → 点击 → 空格/空格/TAB。
6. 回传自雷结果成功：SELF_THUNDER_RESPONSE OK；失败：ERROR + 原因。
单客户端操作与动作锁
出发发送单客户端 TRIGGER。当前动作列只在“出发”列显示执行中。
获取组队码客户端点击固定流程并读剪贴板，回传组队码。
识别队伍状态客户端按配置区域 OCR，回传 [x/n]。
自雷服务端发送 SELF_THUNDER_REQUEST，客户端执行完整自雷。
动作锁客户端/服务端都有“正在执行”的保护。任一自动化动作进行中时，新动作会被拒绝或等待下一轮，避免 OCR、点击、自雷互相抢鼠标/窗口。

关键状态路线摘要

  • 未准备：不参与全局出发与自动开始；可手动执行单客户端操作。
  • 已准备：进入全局出发目标；自动开始时参与 [x/n] 队伍状态判断。
  • 队伍未满：继续 TEAM_READY_REQUEST → TEAM_READY 循环。
  • 队伍满员：触发 TRIGGER → 等 1 秒 → 匹配阶段 OCR。
  • 匹配中：看到“取消行动”显示匹配中；按钮区消失后显示正在加载。
  • 进入对局：左上角 OCR 识别到“机密/普通/绝密”后发送自雷请求。
  • 自雷完成：服务端显示自雷完成，清除该客户端本轮自动开始状态，单客户端回到下一轮 [x/n] 判断。
