# ADB 价格提示后导航路径记录

2026-10-14，Andirons 1.0 曾在两个价格提示入口（固定出发点击后、仓库查找失败后）清理提示成功时执行额外导航。1.1 按用户要求回滚为：直接点击资金位置、连续稳定 OCR 三次、上报金额和准备状态、结束本轮。正常返回准备界面后的导航步骤保留。

1.2 用户确认新增条件分流：清理提示后在 `(324,377,211,53)` 最多检查 5 秒、间隔 150ms，任意一次匹配“方案／仓库／配装”即点击 `(790,665)` 并等待 1000ms，随后走原“一键配装 → 资金识别”流程；不要求文字持续出现满 5 秒，也不再单独查找一次“方案”。5 秒内均未匹配则沿用 1.1 直接资金识别。实际错误、取消及后续一键配装查找超时仍停止。两个提示入口统一适用，正常返回链路不变。

后续版本根据实测日志再次修正：旧区域会读到“保存方案”，导致误入导航；现改为顶部 `(54,6,168,51)` 识别“一键配装”时直接资金回报，或顶部 `(41,0,282,54)` 识别“装备配置”时才执行导航步骤。5 秒无匹配仍直接识别资金，价格提示点击 `(802,50)` 不变。

本次用户另外指定：价格提示的 ADB 清理点击由旧坐标 `(31,26)` 改为 `(802,50)`；保留点击后等待 1500ms、重新全屏 OCR 和约 3 秒的清理时限。此坐标调整独立于下述导航变体，恢复导航步骤时不要顺带恢复旧点击坐标。

日后如需在独立分支恢复提示后导航，将以下步骤插入 `ClientController::executeAdbBossListingSequence` 中 `reportPromptAmountAndReady` 的资金识别之前，两个入口共用该函数：

1. 在 737×440 Windows 客户区 OCR `(324,377,211,53)` 查找“方案”，最多 5 秒、间隔 150ms；找到后按 1280×720 手机坐标 ADB 点击 `(790,665)`，等待 1000ms。
2. OCR `(7,40,126,40)` 查找“一键配装”，兼容 OCR 漏识首字所得“键配装”，最多 5 秒、间隔 150ms；找到后 ADB 点击 `(116,315)`，等待 1000ms。
3. 任一步超时或实际 OCR/ADB 错误时本轮失败，不做资金上报。两步成功后才进入原资金识别。

该变化只属于价格提示回调路径，不修改常规返回准备界面的“出发 → 方案 → 一键配装”链路。

恢复时将 lambda 捕获改为 `[this, &errorText, &readText, &findAndTapRegion, TimeoutMs, PollMs]`，并在 `errorText.clear()` 后、资金识别前恢复以下代码（仅用于以后分支，当前不执行）：

```cpp
if (!findAndTapRegion(QStringLiteral("方案"), 790, 665, QStringLiteral("adb_prompt_plan"), TimeoutMs, PollMs,
    324, 377, 211, 53)
    || !waitForAutomation(1000, errorText)
    || !findAndTapRegion(QStringLiteral("一键配装"), 116, 315, QStringLiteral("adb_quick_loadout"), TimeoutMs, PollMs,
        7, 40, 126, 40)
    || !waitForAutomation(1000, errorText))
    return false;
```

恢复此变体时，回归测试应覆盖两个提示入口成功导航，以及“方案”和“一键配装”分别超时不回报准备的路径。1.0 成品 SHA256：`15D541A4D1A10A3529921187B56954589BC6F57B43C6945E4589C86FD9228626`。
