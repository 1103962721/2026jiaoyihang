# DF_PlayClick 融合倒子弹 OCR 与分组触发设计

日期：2026-07-11

## 1. 目标

将“倒子弹 / 逻辑点击器”项目中的 OCR 数值识别、`OCR 识别结果 ÷ 子弹总数 <= 单价` 判断和满足条件后的执行链路，融合到 `DF_PlayClick` 的 Qt 客户端中；同时精简 `DF_PlayClick` 服务端与客户端界面，形成两个职责明确的独立窗口：

- 服务端：连接管理、币号/老板分组、倒计时、分组顺序和高精度分组延迟调度。
- 客户端：连接服务端、本地保存 OCR 参数、执行 OCR 判断、接收分组触发并按固定坐标点击。

当前设计以 `DF_PlayClick_Server_Qt`、`DF_PlayClick_Client_Qt` 和 `Shared` 为主线，旧 Win32 版本仅作为规则参考。

## 2. 已确认范围

### 2.1 保留和融合

- 保留 TCP 连接、心跳、重连、客户端列表和准备状态。
- 保留服务端倒计时能力。
- 保留客户端真实鼠标/键盘输入机制。
- 融合倒子弹项目中的：
  - OCR 截图；
  - 数字解析；
  - 单价、子弹总数参数；
  - `OCR 结果 ÷ 子弹总数 <= 单价` 判断；
  - 判断满足后的原有执行逻辑；
  - 参数本地保存和恢复。
- OCR 截图区域、币号点击坐标、老板点击坐标均改为全分辨率适配。

### 2.2 移除

从 Qt 服务端/客户端可见 UI 和主业务入口中移除：

- 组队状态解析；
- 自雷；
- 配装；
- 旧的出发按钮与旧出发业务入口；
- 客户端手动取点 UI。

非本次目标的旧代码可在确认无引用后删除；若仍被工程配置或兼容路径引用，则先停止调用，避免无关大范围重构。

### 2.3 新增

- 服务端“全部出发”调度区。
- 服务端高精度“延迟（ms）”参数。
- 服务端顺序选项：
  - 币号组 → 延迟 → 老板组；
  - 老板组 → 延迟 → 币号组。
- 客户端备注类型下拉：币号 / 老板，默认币号；最终类型以服务端保存和下发为准。
- 服务端“上架”按钮：第一阶段只建立空业务入口；只筛选币号客户端，老板客户端永不进入上架目标集合。

## 3. 双窗口 UI 设计

## 3.1 服务端窗口

服务端采用“控制台型”布局：

1. 顶部标题与状态徽标
   - 监听状态；
   - 已连接客户端数量。
2. 监听设置卡片
   - 端口；
   - 启动监听；
   - 停止监听。
3. 全部出发卡片
   - 倒计时（秒，0 表示立即进入分组触发）；
   - 分组延迟（毫秒）；
   - 顺序选择；
   - 全部出发按钮；
   - 上架按钮。
4. 客户端列表
   - IP；
   - 准备/连接状态；
   - 备注类型下拉（币号/老板）；
   - 点击策略说明；
   - 管理操作。
5. 流程预览与连接/操作日志。

上架按钮第一阶段的行为：

- 从当前连接客户端中筛选备注为币号的客户端；
- 调用独立的空方法/占位控制器入口；
- 不向老板发送上架动作；
- 在状态栏或日志中显示本次命中的币号数量和“功能待完善”；
- 不执行倒子弹 OCR 业务，避免将未完成入口伪装成可用功能。

## 3.2 客户端窗口

客户端采用“连接 + OCR + 执行状态”布局：

1. 服务器连接卡片
   - 服务器 IP；
   - 端口；
   - 连接/断开；
   - TCP、心跳和重连状态。
2. OCR 上架判定卡片
   - 单价；
   - 子弹总数；
   - 最近 OCR 原始数值；
   - 单发计算结果；
   - 判断是否满足；
   - OCR 循环或执行状态。
3. 本地执行状态卡片
   - 服务端下发/保存的备注类型；
   - 当前采用币号或老板固定点击坐标；
   - 当前游戏窗口和分辨率适配状态；
   - 最近指令及执行结果。
4. 日志区域。

客户端不再提供 A/B 准星或手动取点。单价、子弹总数及 OCR 相关参数继续由客户端本地输入，并使用现有配置机制持久化。

## 4. 调度和协议设计

## 4.1 客户端类型

协议层为客户端增加明确类型：

- `COIN`：币号；
- `BOSS`：老板。

服务端新连接的默认类型为 `COIN`。服务端修改备注类型后同步给客户端，客户端 UI 显示当前有效类型。协议字段和双方处理逻辑必须同步修改并补充协议测试。

## 4.2 全部出发流程

以“币号 → 老板”为例：

1. 服务端启动倒计时。
2. 倒计时结束后，取得已连接且满足执行条件的币号客户端快照。
3. 服务端对币号组连续发送同一组触发指令：
   - 不添加人为间隔；
   - 网络和线程调度产生的自然耗时不可完全消除；
   - 发送循环必须短小，不穿插 UI、日志格式化或阻塞工作。
4. 币号组发送结束后，执行高精度分组延迟。
5. 延迟结束后，对老板组连续发送触发指令。
6. 服务端记录每组开始、发送完成和实际延迟耗时。

反向顺序使用同一调度器，仅交换两组。

为尽量接近同时：

- 第一版采用“服务端连续快速发送 + 客户端收到即执行”。
- 若实测跨客户端偏差仍不可接受，协议预留后续升级为“下发统一本地执行时间戳”的能力；第一版不提前引入时钟同步复杂度。

## 4.3 高精度延迟

分组间延迟必须与 UI 线程解耦：

- 不允许在服务端 UI 线程直接睡眠。
- 使用专用调度任务/线程。
- 延迟采用粗等待与末端短自旋相结合的策略，并以高精度单调时钟计算目标时刻。
- 自旋窗口保持很短，避免持续高 CPU。
- 重复点击“全部出发”时必须拒绝重入或明确取消旧任务；第一版采用拒绝重入。
- UI 显示设定延迟和最近一次实测延迟，便于验证。

## 5. 客户端 OCR 与点击适配

## 5.1 OCR 逻辑迁移

优先以独立组件迁移，避免把倒子弹的整个窗口类复制进客户端：

- OCR 截图组件；
- OCR 输入动作组件；
- OCR 数字解析器；
- OCR 循环/控制器；
- 参数模型和配置读写。

判定公式保留：

`unitValue = recognizedValue / bulletTotal`

当 `unitValue <= unitPrice` 时进入原项目满足条件后的执行逻辑。必须处理：

- OCR 空结果；
- 非数字或多数字候选；
- 子弹总数为零或非法；
- 目标窗口失效；
- OCR 服务未找到/启动失败；
- 执行中重复触发。

## 5.2 全分辨率适配

采用“参考客户区坐标 + 当前客户区比例映射”，而不是按桌面屏幕尺寸直接缩放：

- 所有参考坐标和 OCR 矩形以游戏窗口客户区为基准；
- 通过目标窗口当前客户区宽高计算 `scaleX`、`scaleY`；
- 矩形四边和点击点独立换算，并在当前客户区范围内裁剪/校验；
- 再通过 Win32 坐标转换得到屏幕坐标；
- 兼容窗口位置变化、不同桌面分辨率及窗口化模式。

基础参考分辨率和最终 OCR/币号/老板参考坐标由用户后续提供。实现阶段先集中定义为可替换常量/配置结构，不把未知数字散落在业务代码中。

## 5.3 固定点击策略

客户端根据有效备注类型选择固定参考点：

- 币号：币号参考点；
- 老板：老板参考点。

点击前必须验证：

- 游戏窗口存在；
- 客户区尺寸有效；
- 映射点落在客户区内；
- 当前无其他自动化动作执行。

## 6. 组件边界

建议新增或调整以下职责边界：

- `Shared/Protocol.h`：客户端类型、分组触发及必要结果消息。
- `ServerController`：服务端入口和状态；不承担精确等待细节。
- 新的服务端分组调度器：客户端快照、组顺序、发送、精确延迟、重入保护。
- `ServerConnectionManager`：单客户端快速发送和客户端类型同步。
- `ClientController`：接收命令、串行化本地动作、反馈结果。
- 新的客户端分辨率映射组件：OCR 矩形和固定点击点映射。
- 从倒子弹迁移的 OCR 组件：截图、解析、循环和输入动作。
- `ClientConfig`：本地单价、子弹总数及 OCR 参数持久化。

## 7. 错误处理和状态反馈

- 无币号或无老板时，允许只执行存在的组，不为缺失组等待无意义延迟。
- 上架无币号目标时只写日志并提示，不产生协议发送。
- 客户端未准备、已断开或窗口无效时跳过，并记录原因。
- OCR 失败不触发满足条件后的点击，保留可诊断日志。
- 服务端调度期间客户端断开时，不阻塞其他客户端。
- 所有工作线程状态更新通过 Qt 信号或排队调用回到 UI 线程。

## 8. 测试和验收

### 8.1 协议与模型测试

- 默认客户端类型为币号；
- 币号/老板序列化与解析；
- 分组触发消息解析；
- 老板不会进入上架目标集合。

### 8.2 调度测试

- 3 个币号 + 1 个老板：币号发送循环无显式等待，随后按延迟触发老板；
- 老板优先时顺序反转；
- 仅币号、仅老板、无客户端；
- 执行期间拒绝第二次触发；
- 延迟 0、1、100 和更大值；
- 记录设定延迟与实测偏差。

### 8.3 OCR 测试

- 沿用并迁移数字解析测试；
- 验证等于、低于和高于单价边界；
- 非法 OCR、空结果、子弹总数为零；
- 配置保存和重新启动恢复。

### 8.4 分辨率映射测试

在参考分辨率确定后，至少覆盖：

- 参考分辨率 100%；
- 1920×1080；
- 2560×1440；
- 其他常见 16:9 分辨率；
- 窗口位置变化；
- 映射越界保护。

### 8.5 UI 验收

- 服务端与客户端是两个独立窗口/可执行程序；
- 被移除功能不再出现在可见 UI；
- 客户端连接能力完整保留；
- 客户端参数可本地保存；
- 上架只命中币号且当前明确显示为占位功能；
- 备注默认币号并可切换为老板；
- 全部出发的顺序、倒计时、延迟和执行状态清晰可见。

## 9. 暂缓项

以下内容不阻塞第一阶段 UI 和骨架整合，但在最终真实执行前必须补齐：

- 原 OCR 基础参考分辨率；
- OCR 参考矩形；
- 币号固定点击参考点；
- 老板固定点击参考点；
- 可接受的跨客户端“近同时”偏差和分组延迟误差指标；
- 上架功能的最终业务动作和协议。
