# 默认准备状态与角色切换 UI 设计

## 目标

- 客户端不再提供“准备”按钮，连接成功后默认处于可执行状态。
- 服务端客户端列表不再显示准备状态。
- 服务端“币号 / 老板”切换由下拉框改为胶囊式双选控件。
- 点击坐标直接以 `X / Y` 同行显示，并随角色切换立即更新。

## 客户端行为

1. 首次连接服务端成功后，客户端自动发送 `READY 1`。
2. 断线自动重连成功后继续恢复 `READY 1`。
3. 用户不需要也不能手动切换准备状态。
4. 保留现有 READY 协议和服务端筛选机制，减少对网络协议及旧逻辑的影响。
5. 若自动发送准备状态失败，按连接发送失败处理，避免服务端显示已连接但无法参与执行。

## 服务端列表

客户端表格由五列调整为四列：

```text
客户端 IP | 备注类型 | 点击坐标 | 操作
```

- 删除“状态”列以及“已准备 / 未准备”文字。
- “备注类型”使用胶囊式双选按钮：`币号 | 老板`。
- 币号选中时使用蓝色高亮，老板选中时使用紫色高亮，未选项使用浅灰背景。
- 切换角色后继续调用现有角色下发逻辑，客户端立即收到新的角色。

## 坐标显示

“点击坐标”列直接同行显示当前角色的 2560×1440 客户区参考坐标：

- 币号：`X: 1756  Y: 1000`
- 老板：`X: 2262  Y: 1159`

坐标列只展示参考坐标；实际点击仍按当前游戏客户区宽高比例适配。

## 兼容与边界

- 新连接默认角色仍为“币号”。
- 仅连接有效且自动准备成功的客户端参与“全部出发”。
- 服务端内部保留 `ready` 字段，避免无关协议重构；UI 不再暴露准备概念。
- “上架”仍保持空方法，本次不修改其行为。
- 不恢复组队状态解析、自雷和配装等已移除的界面入口。

## 验证

- 验证首次连接后服务端可直接执行，无需准备操作。
- 验证断线重连后仍可直接执行。
- 验证服务端表格为四列且不显示准备状态。
- 验证币号 / 老板胶囊按钮切换、颜色和角色下发正确。
- 验证坐标文字随角色显示为对应的 `X / Y`。
- 运行现有相关自动化测试并重新构建客户端、服务端成品。
