## 2. 技术方向

采用 Qt Widgets 精确布局、QSS 和自绘标题栏实现，不切换到 QML，也不将整个窗口改为纯绘制界面。

原因：

- 保留当前 C++ 控制器、网络连接和配置保存结构；
- 可以精确控制颜色、渐变、圆角、边框、字体、间距和控件尺寸；
- 输入框、表格、下拉框和按钮继续使用标准 Qt 控件，交互稳定；
- 改动集中在窗口层，避免无关业务重构。

## 3. 公共窗口框架

服务端和客户端使用一致的视觉结构：

1. 自绘浅灰标题栏；
2. 标题栏右侧三个圆形窗口控制按钮；
3. 渐变应用头部；
4. 浅灰窗口背景；
5. 白色圆角卡片；
6. 深色等宽字体日志区。

三个标题栏按钮依次执行：

- 最小化；
- 最大化或还原；
- 关闭。

自绘标题栏需要支持：

- 按住空白区域拖动窗口；
- 双击标题栏最大化或还原；
- 最大化后恢复；
- Windows 窗口边缘缩放；
- 不允许按钮、输入框等可交互区域误触发窗口拖动。

窗口支持 Windows 高 DPI。所有尺寸使用 Qt 逻辑像素，布局随 DPI 和窗口大小调整。

## 4. 服务端窗口

### 4.1 初始尺寸

- 建议初始尺寸：约 `850×650`；
- 允许用户缩放；
- 设置合理最小尺寸，防止文字换行、按钮重叠和卡片结构破坏；
- 放大时优先扩展客户端表格和日志区域。

### 4.2 应用头部

蓝色渐变头部包含：

- 标题：`服务端调度中心`；
- 副标题：`客户端分组 · 倒计时 · 精确延迟 · 批量触发`；
- 监听状态标签；
- 客户端数量标签。

右侧两个状态标签横向排列，并绑定真实运行状态。

### 4.3 监听设置卡片

卡片包含：

- 监听端口；
- `启动监听`；
- `停止监听`；
- 默认备注类型说明。

两个按钮与端口输入框处于同一横排。按钮设置足够的最小宽度并禁止文字换行，确保“启动监听”和“停止监听”始终完整横向显示。

两个按钮为独立控件：

- 未监听时启用启动按钮、禁用停止按钮；
- 监听中禁用启动按钮、启用停止按钮。

### 4.4 全部出发卡片

卡片包含：

- 倒计时，单位为秒；
- 分组延迟，单位为毫秒；
- `执行` 按钮；
- `上架` 按钮；
- `币号 → 老板`；
- `老板 → 币号`。

`执行` 对应全部出发。币号组或老板组内部不插入人为延迟；第一组完成发送后，再等待设定的精确分组延迟，随后发送第二组。

`上架` 只对币号客户端生效，老板客户端不参与。

### 4.5 客户端列表

严格保留设计稿五列：

1. 客户端 IP；
2. 状态；
3. 备注类型；
4. 点击坐标策略；
5. 操作。

备注类型使用下拉框，选项为：

- 币号；
- 老板。

新连接客户端默认币号。

点击坐标策略根据备注显示：

- `币号固定点 · 自适配`；
- `老板固定点 · 自适配`。

列表数据必须来自真实客户端连接状态，不写死预览中的 IP、数量和状态。

### 4.6 流程预览与日志

流程预览根据以下数据实时生成：

- 当前顺序；
- 币号客户端数量；
- 老板客户端数量；
- 分组延迟。

底部日志使用设计稿中的深色样式，记录监听、连接、备注变更、调度和异常信息。

## 5. 客户端窗口

### 5.1 初始尺寸

- 建议初始尺寸：约 `620×650`；
- 允许用户缩放；
- 设置合理最小尺寸；
- 缩放时保持卡片顺序和控件层级，不出现文字拥挤。

### 5.2 应用头部

绿色渐变头部包含：

- 标题：`客户端执行端`；
- 副标题：`服务器连接 · OCR 上架判定 · 本地点击`；
- 真实连接状态标签。

### 5.3 连接服务器卡片

卡片包含：

- 服务器 IP；
- 端口；
- `连接`；
- `断开`；
- TCP、心跳、自动重连说明；
- 当前连接或重连状态。

连接与断开使用两个独立按钮，并根据真实连接状态启用或禁用。

服务器 IP 和端口继续由客户端本地读取和保存。

### 5.4 OCR 上架判定卡片

卡片包含：

- 单价；
- 子弹总数；
- OCR 识别结果；
- `OCR 结果 ÷ 子弹总数`；
- 设定单价；
- 最终判定状态；
- 全分辨率截图区域适配说明。

单价和子弹总数修改完成后自动保存到客户端本地，不增加“保存”按钮。

无效输入不得覆盖此前保存的有效配置。

尚未接入真实 OCR 或尚未获得识别结果时，显示明确的等待状态，不使用预览稿中的示例数字伪装真实识别结果。

真实 OCR 迁移、参考分辨率和 OCR 区域坐标不属于本次视觉复现的完成范围；后续获得参数后再接入。

### 5.5 本机执行状态卡片

卡片展示：

- 服务端下发的备注类型；
- 对应固定点击坐标的适配状态；
- 最近指令；
- 最近执行结果。

客户端不提供手动取点入口。固定点击点由后续提供的参考坐标按游戏客户区分辨率映射。

### 5.6 日志

底部日志使用与服务端一致的深色样式，记录：

- 连接；
- 断开；
- 重连；
- 指令接收；
- OCR 状态；
- 本地点击执行结果；
- 错误信息。

## 6. 数据流与职责

### 6.1 服务端

服务端窗口只负责展示和发起：

- 监听控制；
- 客户端连接状态；
- 客户端备注类型；
- 倒计时与分组延迟；
- 发送顺序；
- 全部出发；
- 币号上架；
- 调度日志。

窗口不得自行复制网络状态，所有动态内容从 `ServerController` 及相关模型读取。

### 6.2 客户端

客户端窗口负责展示和输入：

- 服务器连接参数；
- 本地 OCR 参数；
- OCR 判定结果；
- 服务端下发的备注类型；
- 固定坐标适配状态；
- 本地执行和连接日志。

窗口不得伪造 OCR 数值或执行成功状态。

### 6.3 线程约束

网络、OCR 或执行线程产生的状态必须通过 Qt 信号进入 UI 线程更新控件，禁止后台线程直接操作 UI。

## 7. 异常与边界状态

- IP、端口、单价或子弹总数无效时，在对应卡片内显示红色提示；
- 网络断开、重连、OCR 等待、OCR 失败和指令失败使用统一状态颜色并写入日志；
- 没有币号客户端时，上架不发送指令并提示；
- 某一发送分组为空时，全部出发跳过空组，不进行无意义等待；
- 客户端列表为空时保持完整表头和空状态提示；
- 控件忙碌时禁止重复触发造成并发动作；
- 窗口缩放不得导致关键按钮文字折行。

## 8. 编码和修改约束

修改 `.cpp`、`.h`、`.rc` 等文件前必须检测原编码和换行风格。

- GBK/CP936 文件继续按 GBK/CP936 写回；
- UTF-8 文件继续按 UTF-8 写回；
- 保持 CRLF；
- 不进行未经确认编码的整文件重写；
- 修改后检查 `U+FFFD（Unicode replacement character）`、C4819、字符串断裂和非法字符；
- 核心窗口控制、状态绑定、坐标映射和跨线程 UI 逻辑补充简短中文注释。
